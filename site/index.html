How it's built

  1. Spend joins to leads on campaign ID, pulled from the end of the UTM (name__id). The extraction tolerates case, stray spaces and URL-encoding. Campaign names are display-only: the latest name is shown, and old names are kept as a "renamed" hint.
  2. Outcomes belong to the lead's creation date. A campaign's spend on a day is compared with what those leads went on to do, whenever the sale happened.
  3. Rules, not a language model, write "what moved". Last 7 days vs the 28 before: zero leads with spend for 3 days, CPL up 25% or more, CPL down 20% or more (only above ₹30k weekly spend), and sale rate under 15% of average in mature cohorts. Each is sized in rupees.
  4. One small data file, one static page. A Python pipeline turns raw spend rows and lead records into daily facts per campaign. The page aggregates them for any range or channel in the browser. GitHub Actions runs the tests and rebuilds it every morning. The same join is written in BigQuery SQL in the repo.
